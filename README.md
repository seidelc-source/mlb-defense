# MLB Defense — defensive positioning engine

Recommends legal defensive alignments (7 fielders) for a batter × pitcher ×
ballpark × weather scenario, scored by a calibrated out-probability surface
built from ~6.8M Statcast pitches (2016–2025).

**▶ Live static demo:** https://seidelc-source.github.io/mlb-defense/
(precomputed featured matchups — the full app runs locally, see below)

![stack](https://img.shields.io/badge/FastAPI-Python%203.11-009688) ![stack](https://img.shields.io/badge/React%2018-TypeScript-3178C6)

## What it does

- **Field View** — pick a matchup, get a legal alignment (MLB 2023+ shift
  rules enforced) with per-position placements, a coverage heatmap, weather
  carry/drift effects, and alternatives.
- **Spray Analysis** — 8-zone spray charts per batter with season/handedness
  filters and a recency-weighted all-season blend.
- **Player Profiles** — Statcast fielding metrics (OAA, sprint speed, arm),
  pitcher batted-ball profiles, reach-radius model, injury degradation.

## Honest claims (the interesting part)

This is a portfolio project whose modeling claims are outcome-validated and
deliberately scoped — see `documentation/` for the full evidence base:

- The **P(out | standard alignment) surface is calibrated** per-trajectory
  (isotonic, LOSO reliability gate) against realized outcomes.
- The **positioning direction** (`predicted_oaa_delta`) is outcome-validated;
  absolute out/hit percentages are population-level only and are labeled as
  such in the UI.
- The pull-based **shift-type suggestion is a heuristic** — testing showed it
  does *not* beat "shift broadly", and the UI says so.
- Experiment log with negative results: `documentation/EXPERIMENTS.md`;
  current trust status: `documentation/TRUST_REPORT.md`.

## Run the full app locally

```bash
# Postgres + Redis via Homebrew, then:
python start.py                      # backend :8000 + frontend :5173

# one-time data bootstrap (see CLAUDE.md for details)
cd backend
python -m scripts.seed
python -m scripts.ingest_all --season 2024 --start 2024-03-28 --end 2024-09-29
```

## Static demo

The GitHub Pages build (`VITE_DEMO_MODE=true`) serves prebaked engine output
for 7 featured matchups × 5 weather presets × 3 optimization targets —
generated by `backend/scripts/build_demo_fixtures.py` from the live engine.
Live-only features (fielder-drag re-scoring, arbitrary matchups, ingest) are
disabled there.

## Layout

- `backend/` — FastAPI, SQLAlchemy async, alignment engine + calibration
  (`app/services/alignment/`), Statcast ingest, APScheduler jobs
- `frontend/` — React 18 + TypeScript, D3 field rendering, Zustand,
  TanStack Query
- `documentation/` — operating contract, data knowledge, modeling evidence,
  experiments, trust report, roadmap
